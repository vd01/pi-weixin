# pi WeChat Agent 扩展

在**微信里查看 pi agent 的执行结果（只推最终结果，不含中间过程）**，直接**回复消息下发命令**。
使用微信给 OpenClaw 开放的官方 bot 接口（腾讯 iLink），**扫码即可绑定**，无需注册公众号/开放平台。

## 功能

- **扫码绑定**：终端执行 `/wx`，用手机微信扫描终端中的二维码并确认，即完成绑定；凭据持久化到本地，重启自动恢复连接
- **结果推送**：pi 每次任务结束后，自动把最终 assistant 回复推送到微信（不含工具调用、思考等中间过程；长文本自动分段），同一条回复不会因自动续跑而重复推送
- **微信任务优先回**：微信下发的任务不等整轮工作结束 —— 回复文本一产生，去抖 20s 后立即推送（长工具链/子代理/goal 续跑时，原先要等 `agent_settled`，实测可拖几分钟到几十分钟）；任务处理期间产生的后续新回复也会继续推送
- **空闲提醒（决定权在你）**：最近一条消息来自微信、agent 这一轮已结束（不要求推送成功），但之后一直空闲超过 3 分钟、
  且看起来还有没做完的活时，扩展只**往微信推一条提醒**：
  ```
  agent 已空闲 3m00s，看起来还有没做完的活（依据：回复含进度/等待用语）。
  回复「继续」让它接着干；发「状态」看它在做什么；不用了忽略本条即可。
  ```
  **扩展不再自动催 agent**；你回「继续」时才真正推动它。同一任务只提醒一次。
  是否有后续任务用黑名单判断（只有明确“已无待办 / 在等你决策 / 无需处理”才不提醒）。
  关闭提醒：`/wx nudge off`
- **远程下发命令**：微信里直接发文本，作为任务下发给 pi（agent 忙时自动排队）；任务结束推送结果
- **内置微信命令**：
  | 发送 | 作用 |
  |------|------|
  | `帮助` | 查看命令列表 |
  | `状态` | agent 空闲时只回「空闲」；执行中**不打断**，返回：正在执行的任务 / 当前动作与耗时 / 最近几步 / 后续计划 + CPU·内存·GPU |
  | `打断` | 终止当前执行，并让 agent **先汇报现状与后续计划**，之后进入正常对话 |
  | `继续` | 让空闲的 agent 接着干（收到空闲提醒后由你决定；扩展不会自动催） |
  | `停止` | 只中断当前任务（不要求汇报） |
  | `静默` | 切换推送模式（开启后仅微信下发的任务回结果） |
  | `解绑` | 解除绑定并清除本地凭据 |

  `状态` 是**纯观测**：只读会话分支（最近任务/最近回复里的计划）、扩展自己记的工具事件（当前工具与耗时）、
  `/proc/stat` + `nvidia-smi`（CPU/内存/GPU），**不调用模型、不向 agent 下发任何消息**，所以不会影响正在跑的任务。
  返回控制在 1 条微信消息内（实测约 300 字），不浪费主动消息额度。

  `打断` 的实际行为：`abort()` 终止当前这一轮 → 把「任务/中断时正在跑的命令/中断前最近动作」作为快照
  连同「先汇报再停下」的指令发给 agent → 汇报文本产生后立即推回微信。
  ⚠️ 前台 `bash` 子进程会被终止；用 `nohup`／`setsid` 起的后台进程不受影响。

## 终端命令

| 命令 | 作用 |
|------|------|
| `/wx` | 扫码绑定（已绑定时提示） |
| `/wx status` | 查看通道状态 |
| `/wx stop` | 停止通道 |
| `/wx reconnect` | 接管连接（从其他 pi 实例抢过来，原实例自动退出） |
| `/wx unbind` | 解绑并清除本地凭据 |
| `/wx widget [on\|off]` | 开关输入框上方的微信状态提示 |
| `/wx debug [on\|off]` | 后台日志是否输出到终端（默认关闭，日志仍写入 `weixin.log`） |
| `/wx nudge [on\|off]` | 空闲提醒开关（默认开启；只提醒人，不催 agent） |
| `/wx help` | 显示子命令帮助（输入 `/wx ` 也有自动补全） |

## 安装

方式一（推荐）：放入全局扩展目录：

```bash
mkdir -p ~/.pi/agent/extensions
cp -r weixin-agent ~/.pi/agent/extensions/
# 或使用软链接： ln -sfn $(pwd)/weixin-agent ~/.pi/agent/extensions/weixin-agent
```

方式二：项目本地 `.pi/extensions/`，或 `pi -e ./weixin-agent` 快速测试。

安装后在扩展目录执行 `npm install`（依赖 `qrcode` 用于终端渲染二维码），重启 pi 或执行 `/reload`。

## 使用流程

1. 启动 pi，执行 `/wx`
2. 终端显示二维码（下方附备用链接），用微信扫码
3. 首次绑定时按提示输入手机微信上显示的验证码
4. 绑定成功后微信收到欢迎消息，之后即可：
   - 微信发「跑一下测试并总结失败原因」→ pi 执行 → 微信收到最终结果
   - 在电脑前让 pi 干活，人在微信里收到完成通知与结果

## 多实例说明

同一台电脑跑多个 pi 实例时，微信连接**同一时间只属于一个实例**（锁文件 `~/.pi/agent/weixin/owner.json`）：

- 后启动的实例不会重复连接，终端会提示当前持有者
- 想把连接切到某个实例：在该实例里执行 `/wx reconnect` 接管，原实例下次轮询时自动退出
- 每条结果推送都带 `[会话名]` 前缀，可区分来自哪个实例/项目
- 微信下发的任务只会被持有连接的实例执行，不会重复跑

## 文件位置

- 凭据与状态：`~/.pi/agent/weixin/`
  - `credentials.json` — bot 凭据（token，权限 0600，**请勿外泄**）
  - `syncbuf.txt` — 消息同步游标（避免重启后重复拉取）
  - `context.json` — 会话上下文令牌（用于主动推送）
  - `settings.json` — 静默开关 / 状态提示 / 终端调试 / 空闲提醒（`silent` / `widget` / `debug` / `nudge`）
  - `weixin.log` — 后台运行日志（推送失败、长轮询错误等，默认不输出到终端）
  - `owner.json` — 连接所有权锁（多实例协调）

## 协议说明

扩展直接实现了微信官方 iLink bot 协议（与腾讯 `@tencent-weixin/openclaw-weixin` 插件同源）：

- 扫码：`POST /ilink/bot/get_bot_qrcode` + `GET /ilink/bot/get_qrcode_status`（固定服务 `ilinkai.weixin.qq.com`）
- 收发：`POST /ilink/bot/getupdates`（长轮询）、`/ilink/bot/sendmessage`、`/ilink/bot/msg/notifystart|notifystop`

## 微信侧限制（主动推送的硬约束）

微信 ClawBot / iLink 对「机器人主动发消息」有两个约束，直接决定我们能推多少、什么时候能推：

| 限制 | 数值 | 依据 |
|---|---|---|
| 消息窗口 | 用户最后一次消息后 **24 小时**；此后 context_token 失效，无法主动触达，需用户再发一条 | 官方协议说明与腾讯 issue [#202](https://github.com/Tencent/openclaw-weixin/issues/202) |
| 每窗口主动消息额度 | 约 **10 条** | 同上；本扩展日志实测吻合（见下） |
| 长任务回复失效 | 社区报告长任务（~160s）后回复发不出去 | OpenClaw issue [#61174](https://github.com/openclaw/openclaw/issues/61174)（腾讯侧未确认） |

本扩展 2026-09-30 的实测时间线（同一实例，日志 + 会话记录）：

```
01:05:32  用户发消息（开窗口）
01:11~06:38  共 10 条不同回复推送全部成功
09:41 起   连续 6 次 ret=-2 prepare failed（第 11 条开始），期间用户 8.6h 未发消息
10:45:35  用户又发一条消息
11:42 起   推送立即恢复成功
```

注意：**长文本按 1500 字分段，每段都算 1 条主动消息**；自主续跑（goal）的输出同样消耗额度。
额度耗尽后只能等用户在微信里再发一条消息。

## 延迟排查

`~/.pi/agent/weixin/weixin.log` 每次都会记录三段可核算的延迟，出问题时直接看这个文件：

| 日志行 | 含义 |
|---|---|
| `收到微信任务（微信发出→本机 Ns；pi 忙，已排队 followUp / 空闲，立即执行）` | 微信→本机的链路延迟，以及是否卡在 pi 的排队里 |
| `已推送 条目 xxx（来源=微信任务早推/落定；文本产生→送达 Ns；微信下发→送达 Ns；本窗口第 N 条主动消息）` | 回复文本产生到真正送出的延迟，以及额度消耗进度 |
| `推送失败(连续 N 次): sendmessage ret=-2 errmsg=prepare failed（token 年龄 Ns；本窗口已发 N 条主动消息）` | 微信侧拒收：额度耗尽（≈10 条）或空闲超过窗口；用 `token 年龄` 与已发条数即可区分 |
| `收到新消息，主动消息计数归零（上一窗口已发 N 条）` | 用户新消息重置额度，同时告诉你上一窗口用了多少条 |

`/wx status` 会同样显示「主动消息: 本窗口已发 N 条（token 年龄 Ns）」。
微信主动推送有会话窗口限制：长时间不交互后，即使发出去也可能被 `ret=-2 prepare failed` 拒掉，
重新在微信里发一条消息即可恢复。

## 注意事项

- **同一条回复只推送一次**：每次 agent 落定都会推送「最后一条带文本的回复」，
  但自动续跑（goal 继续、重试、只调工具的续轮）不会产生新文本，
  此时会把上一条回复重复推给微信。现已按会话条目 id 去重：
  同一轮多次落定不重复推，只有出现**新的回复文本**才会再推；
  推送失败的条目不会标记为已发送，下次落定会自动重试（不丢结果）
- 若不想接收终端侧任务的推送（例如 goal 自主续跑的阶段性输出），在微信里发「静默」，
  切为「仅微信下发的任务回结果」；用 `/wx status` 可查看当前模式
- **后台故障不会往输入框附近刷提示**：长轮询报错、结果推送失败等只写入
  `~/.pi/agent/weixin/weixin.log`（超过 256 KB 自动截断），终端保持安静；
  需要现场排查时执行 `/wx debug on`（或环境变量 `WEIXIN_DEBUG=1`）让日志同时输出到终端，
  用 `/wx status` 查看结果推送是否连续失败及最近一次失败原因
- 微信侧只会在故障持续时最多每 5 分钟收到一条故障回报，避免刷屏
- 结果推送依赖微信侧窗口机制：绑定后请保持与 bot 有过交互；长时间未交互后主动推送可能被微信限制（重新发一条消息即可恢复）
- 暂仅支持文本消息（图片/语音/文件收发可基于 `ilink.ts` 中的 CDN 协议扩展）
- bot token 是敏感凭据，`credentials.json` 不要提交到代码仓库
